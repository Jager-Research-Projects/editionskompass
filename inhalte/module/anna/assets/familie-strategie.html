Unsere Musterstrategie

  1. Mit einem begrenzten TEI-Modell und vorbereiteter oXygen-/Git-Umgebung beginnen; Beratung und Lizenz klären.
  2. Änderungen vergleichen, als Commit festhalten und regelmäßig zum privaten Arbeitsrepo übertragen; den Rückweg testen.
  3. Geprüfte Editionsdaten in einem eigenen Publikationsrepo freigeben; eine kleine Website und eine Archivfassung nach Bedarf ergänzen.

Begriffe für den Arbeitsweg

Git und Plattform

Git hält Dateistände und ihre Beziehungen fest. GitHub und GitLab ergänzen Hosting, Berechtigungen, Diskussionen und automatisierte Prüfabläufe.

Git-Repositorium, kurz Repo

Ein Repo enthält Dateien und ihre Git-Geschichte. Ein Arbeitsrepo dient der Bearbeitung; ein Publikationsrepo wird für seine Leserinnen und Leser kuratiert.

Commit und Übertragen

Ein Commit hält einen Änderungsschritt lokal fest. Erst das Übertragen zum entfernten Repo macht ihn auch dort verfügbar.

Tag, Release und Archivfassung

Ein Tag markiert einen Git-Stand. Ein Release bündelt eine bewusst freigegebene Ausgabe mit Beschreibung. Eine unabhängige Archivfassung erhält den Bestand mit Metadaten.

Editionsdaten, Frontend und Interface

Die wissenschaftlich verantworteten Daten tragen Texte und editorische Beziehungen. Das technische Frontend stellt ein Interface zur Erschließung der digitalen Edition bereit. Interface bezeichnet den gestalteten Zugang aus Nutzungsperspektive.

Prüfung und fachliche Abnahme

XML-Wohlgeformtheit, Schema-Prüfung und Funktionstests prüfen unterschiedliche Eigenschaften. Die editorische Abnahme beurteilt zusätzlich den wissenschaftlichen Inhalt. Ein grüner Test ersetzt sie nicht.

Durchsicht und Gutachten

Review bezeichnet hier eine vereinbarte technische oder redaktionelle Durchsicht. Ein externes wissenschaftliches Gutachten hat einen eigenen Auftrag. GitLab nennt Änderungsvorschläge Merge Requests, GitHub Pull Requests.

Sicherung und Betrieb

Regelmäßige Commits und Übertragung auf ein verlässlich betriebenes Uni-GitLab können Teil einer Sicherungsstrategie sein. Dateien außerhalb des Repos, Wiederherstellung, Archivierung und laufender Dienstbetrieb brauchen eigene Regelungen.
